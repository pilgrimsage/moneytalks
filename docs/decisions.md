# Key Decisions

The short list of choices that shape the code. Details live in the doc named on each line.

## Product
- **Personal use, single owner.** Every user-owned table still has `user_id`, but there is no tenant layer, plans, billing or admin UI. Management is by console commands.
- **WhatsApp is the only UI.** Reports and exports are generated by code; the model never writes a number.
- **Haiku only.** Sonnet escalation exists behind `AI_ESCALATION_ENABLED` and is off (`ai.md`).
- **Notifications are opt-in and template-first**, because free-form replies only work inside WhatsApp's 24-hour window (`whatsapp.md`).
- **Voice** uses a separate speech-to-text vendor (`STT_*`), off by default; every voice or photo record needs a Confirm tap.

## Accounting (`ledger.md`)
- One double-entry ledger (no parallel "transactions" tables). Categories are a dimension on an entry, not accounts.
- Money is **integer minor units + currency**; balances are derived, never stored.
- Append-only: undo and correction are reversing entries. Recurring "expected" items are not ledger entries.
- Ambiguity (which account, which person, which category) is a question to the user, never a guess.

## AI (`ai.md`)
- The model returns a structured **proposal**; validated code decides. Its self-reported confidence is not trusted; the amount is cross-checked against the raw text.
- The model returns a *date spec*, never a resolved date, and never database ids. Reports are templates over SQL, not model text.

## Hosting: Hostinger shared hosting + MySQL/MariaDB (`deployment.md`)
| Not available | What we do instead |
|---|---|
| Deferred triggers / Postgres constraints | Debit = credit check inside `LedgerService` before commit, nightly `ledger:verify`, per-transaction hash, immutability triggers where allowed |
| `jsonb`, partial indexes, RLS | `JSON` only as opaque blobs; defaults copied per user so uniqueness is a plain `UNIQUE` |
| Redis, Horizon, daemons | `database` queue/cache/session; cron every minute runs `queue:work --stop-when-empty` and the scheduler |
| Managed point-in-time backups | Our own encrypted nightly dump, verified by restoring into a scratch database |
| UUIDv7 | ULIDs (`HasUlids`); `BIGINT` for entries and logs |
